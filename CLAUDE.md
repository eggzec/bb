# CLAUDE.md — Project Conventions & Behavior Guide

## Project Purpose
`bb` is a Bitbucket CLI tool and Python SDK inspired by `gh` (GitHub CLI). It supports both **Bitbucket Cloud** and **Bitbucket Data Center** as separate targets under a shared CLI.

- **CLI** (`src/bb/cli/`): Typer-based commands — shared across targets, dispatches to the right SDK
- **Cloud SDK** (`src/bb/cloud/sdk/`): Hand-written wrappers over the generated Cloud API layer
- **Datacenter SDK** (`src/bb/datacenter/sdk/`): Hand-written wrappers over the generated DC API layer
- **Generated (Cloud)**: `src/bb/cloud/{api,models,client.py,types.py,errors.py}` — never edit manually
- **Generated (DC)**: `src/bb/datacenter/{api,models,client.py,types.py,errors.py}` — never edit manually

**Both Cloud SDK and DC SDK are implemented. CLI comes after SDK is complete.**

## Generated API Call Structure

Every endpoint module under `src/bb/cloud/api/<tag>/<method>_<path>.py` has this layout:

```
_get_kwargs()       → builds httpx request dict (URL, params, body, headers)
_parse_response()   → maps status codes to typed model or None
_build_response()   → wraps httpx.Response into Response[T]
sync_detailed()     → sync call → Response[T]          (always generated)
sync()              → sync call → T | None              (only if response has parsed type)
asyncio_detailed()  → async call → Response[T]          (always)
asyncio()           → async call → T | None             (only if parsed type)
```

**Use `sync()` internally in SDK wrappers. Never expose `sync`, `sync_detailed`, or generated module names in the SDK public API.**

### Two client types (both autogenerated in `client.py`)

| | `Client` | `AuthenticatedClient` |
|---|---|---|
| Use | Public/unauthenticated endpoints | Secured endpoints (most BB APIs) |
| Auth | None | Injects `Authorization: Bearer <token>` header |
| Construction | `Client(base_url=..., headers=...)` | `AuthenticatedClient(base_url=..., token=BB_TOKEN)` |

Both are attrs `@define` classes. httpx.Client is lazy-initialised on first request.

### Endpoint naming convention

`{http_method}_{url_path_with_slashes_as_underscores}.py`, path params stripped of braces:
- `GET /repositories/{workspace}` → `get_repositories_workspace.py`
- `DELETE /repositories/{workspace}/{repo_slug}/hooks/{uid}` → `delete_repositories_workspace_repo_slug_hooks_uid.py`

## SDK Design — Current Focus

SDK wrappers live in `src/bb/cloud/sdk/`. Each resource module:
- Calls `sync()` from the generated API internally
- Unwraps the union return type (`isinstance` check inside the wrapper, not at the call site)
- Returns clean Python objects
- Never exposes `sync`, `sync_detailed`, `asyncio`, or generated module names

Public surface via `src/bb/cloud/__init__.py` with `__all__`.

**Do NOT build CLI until SDK is complete.**

## cmd_outputs Naming Convention

Always separate stdout and stderr. Always timestamped:

```bash
TS=$(date +%Y%m%d_%H%M%S)
some-command \
  > cmd_outputs/${TS}_<name>_stdout.txt \
  2> cmd_outputs/${TS}_<name>_stderr.txt

# Sample — never open whole files:
head -50 cmd_outputs/${TS}_<name>_stdout.txt
grep -i "error\|warning" cmd_outputs/${TS}_<name>_stderr.txt | head -20
tail -10 cmd_outputs/${TS}_<name>_stdout.txt
```

## Generator Workflow (Data Center)

Same pattern as Cloud but using `config/generator_dc.yml` and `bb_datacenter_fixed.openapi.json`.
use the makefile targets for the generation and comparision of the this.

**DC-specific notes:**
- Pagination uses `start`/`limit` (not `page`/`pagelen`). Responses have `is_last_page`, `next_page_start`, `values`.
- Auth: `PersonalAccessTokenAuth` (Bearer) or `BasicAuth` (Basic). Set `BB_DC_TOKEN` or `BB_DC_USERNAME`+`BB_DC_PASSWORD`, plus `BB_DC_BASE_URL`.
- DC endpoint names use `operationId` (not path-based), so names are non-descriptive (e.g., `get_3.py`, `create_1.py`). Use `head` + grep to discover the right module.
- Post-hooks: `apply_deprecations_dc.py` patches deprecated endpoints; ruff fixes/formats.

## API Conformance Testing (schemathesis)

Schemathesis tests the live BB Cloud API against `bb_cloud_fixed.openapi.json`. It runs GET-only, one example per operation, and reports every discrepancy between the spec and what Bitbucket actually returns.

### Credentials — `.env` file (project root, gitignored)

Copy `.env.example` to `.env` and fill in `BB_EMAIL`, `BB_TOKEN`, `BB_WORKSPACE`.  
`BB_TOKEN` is an Atlassian API token from `id.atlassian.com/manage-profile/security/api-tokens`.  
Optionally set `BB_REPO_SLUG` — run `schema-discover-cloud` to find the best value.

**Critical:** always use `httpx` (not `urllib.request.urlopen`) in any script that calls the BB API.  
`urllib` follows Bitbucket's redirect and silently drops the `Authorization` header → 401.  
`httpx.get(..., follow_redirects=True)` preserves auth on same-host redirects.

### Commands

```bash
make schema-discover-cloud   # probe workspace state, suggest BB_REPO_SLUG for .env
make schema-test-cloud       # run schemathesis (~150 ops, ~2-3 min) — exits non-zero on failures
```

Reports are written to `cmd_outputs/` with timestamp prefix:
- `*_schemathesis_cloud_stdout.txt` — full terminal output with per-failure details
- `*_schemathesis_cloud.xml` — JUnit XML (CI-compatible)
- `*_schemathesis_cloud.ndjson` — machine-parseable event stream

### Interpreting failures

Two classes — you must distinguish them:

**Real spec bugs** (fix in `bb_cloud_fixed.openapi.json`):
- Undocumented status codes (403, 410) on endpoints tested with your real workspace
- Response schema violations (extra properties, wrong types) on 200 responses
- Content-Type mismatches on real responses

**Expected noise** (caused by random path params — no seed data):
- Undocumented 404 on repo-scoped endpoints where the spec only documents 200 — random path
  params (`workspace=0`, `repo_slug=0`) hit non-existent resources
- HTML Content-Type on certain 404s with pathological path values

Distinguishing rule: if the same failure appears in `tests/cloud/live/` with real data → real bug.  
If it only appears with schemathesis's random `0` values → likely noise.

For each confirmed real bug: patch `bb_cloud_fixed.openapi.json` with `jq` surgery, then run  
`make generate-cloud` and `make diff-cloud` to verify the fix flows into the generated code.
